# Session Summary: 2025-10-22

## Overview
Today's session focused on reviewing and enhancing the backend architecture, implementing enterprise-grade patterns, and setting up the Git repository. Significant progress was made on models, views, and establishing best practices.

## Major Accomplishments

### 1. Git Repository Setup
- Connected local repository to GitHub: `michacurri/ats-resume-checker`
- Renamed branch from `master` to `main`
- Reviewed and optimized `.gitignore` files (root and frontend)
- Added `.cursor/` to frontend `.gitignore` for Cursor IDE

### 2. Database Models Enhanced
**Resume Model:**
- Added `is_active` field with index for future multi-resume support
- Added `related_name='resumes'` to user ForeignKey
- Removed `unique=True` from `sha256` (enforced in business logic instead)
- Added composite index on `(user, is_active)` for performance
- Added `__str__` method for admin readability
- Added `ordering = ['-uploaded_at']` for consistent results

**JobDescription Model:**
- Changed `source_url` to nullable and unique
- Added `db_index=True` on `sha256` for deduplication
- Designed for sharing across users

**UserJobInterest Model (New):**
- Tracks which users are interested in which jobs
- Many-to-many relationship via explicit through model
- `unique_together` constraint on `(user, job)`
- Enables personalized job recommendations and TTL logic

**Evaluation Model:**
- Complete schema for AI evaluation results
- Tracks: `ats_score`, `match_score`, `missing_keywords`, `suggestions`
- Includes `prompt_hash` for caching
- Tracks `tokens_used` for cost monitoring

### 3. ViewSets Implemented
**ResumeViewSet:**
- Added `IsAuthenticated` permission class
- Implemented `get_queryset()` for user isolation
- Implemented `perform_create()` with:
  - SHA-256 hashing of text_blob
  - Single active resume enforcement (deactivates previous resumes)
  - Automatic user assignment
- Added `@action` endpoint for getting active resume: `GET /resumes/active/`

**Other ViewSets:**
- JobDescriptionViewSet and EvaluationViewSet created with basic CRUD
- Ready for AI integration and job scraping logic

### 4. Enterprise Patterns Learned & Implemented

**Database Optimization:**
- Composite indexes for fast queries: `Index(fields=['user', 'is_active'])`
- Field-level indexes: `db_index=True` on frequently queried fields
- Default ordering on models

**Code Quality:**
- Docstrings (Python's equivalent of JSDoc) on all methods
- `__str__` methods for human-readable model representations
- `related_name` on ForeignKeys for clean reverse lookups

**Django REST Framework Patterns:**
- `get_queryset()`: Automatically called by DRF for filtering (user isolation)
- `perform_create()`: Override for custom business logic on creation
- `@action` decorator: Create custom endpoints beyond CRUD

**Business Logic:**
- Single active resume enforced in view, not schema (growth-ready)
- Shared job descriptions across users (efficiency)
- User job interest tracking (personalization)

### 5. Technical Knowledge Gained

**Python/Django Concepts:**
- Docstrings vs comments (docstrings accessible at runtime)
- `related_name` for intuitive reverse ForeignKey lookups
- `get_queryset()` lifecycle and automatic invocation
- `@action(detail=True/False)` for custom endpoints
- When to use `*args, **kwargs` in method signatures

**Git Workflow:**
- Branch renaming: `git branch -M main`
- Remote setup: `git remote add origin <url>`
- Handling "remote already exists" errors

**Enterprise Patterns:**
- MVP vs growth balance (enforce in code, not schema)
- Composite indexes for performance
